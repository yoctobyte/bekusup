## What Changed Most Recently

### 1. Bare invocation is now configurable

There is now a config setting:

- `run_policy.run_without_command`

Behavior:

- if `false`, running `./bekusup-cli.sh` with no command opens an interactive menu
- if `true`, running `./bekusup-cli.sh` with no command immediately runs backup

This setting is now asked by the wizard and preserved during reconfiguration.

### 2. Interactive configuration exists after first-run too

The user no longer loses convenience once `config.yaml` exists.

No-arg menu with existing config now offers:

- run now
- scan
- enroll
- reconfigure config
- quit

### 3. Dry-run remains the training-wheels default

The current constant is still:

- `DEFAULT_DRY_RUN = True`

This is intentional for now.

## Important Behavior Notes

### Dry-run semantics

Dry-run currently means:

- no durable session writes
- no session finalization on disk
- no index updates from the run
- no automatic mount attempts

If a target disk is not already mounted, dry-run will refuse and tell the user to mount it manually first.

### Convenience vs safety

The tool is more user-friendly now, but still intentionally conservative where mistakes are dangerous:

- disk enrollment is still explicit
- trust still depends on marker + local index behavior
- overlapping invocations are still locked out
- dry-run remains default unless explicitly overridden

## Remaining Sharp Edges

These are the main things still worth tightening:

### 1. Starter config is still opinionated

The wizard defaults to:

- one local host
- one source path under `/home/$USER`

That is convenient, but still a guess.

### 2. Source/destination overlap protection is still worth strengthening

If the backup disk mountpoint ever sits under a configured source tree, the tool should be very explicit about refusing or excluding that overlap.

### 3. Dry-run is not a full simulation

It still performs:

- real disk scanning
- real trust checks
- real reachability probes

That is acceptable, but should be understood clearly.

### 4. The project is still not "finished"

The main remaining implementation gaps are still:

- richer operator query support in the index
- clearer and more durable host outcome history
- continued hardening of multi-disk policy
- stronger trust/identity reconciliation
- more operator-facing clarity around what happened in a run
